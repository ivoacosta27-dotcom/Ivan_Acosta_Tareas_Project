Idea general

Maoui Fragance es una perfumería ficticia. Para ella voy a desarrollar un sistema web donde las personas se pueden registrar e iniciar sesión, y donde el administrador del local puede ver, buscar, editar y archivar a los usuarios registrados.

El sistema hace un CRUD completo sobre una tabla de usuarios: crear (registro), leer (listado y búsqueda), actualizar (edición) y "borrar" (archivado, sin eliminar el dato de verdad).

Tecnologías que voy a usar:

  • Frontend: HTML5 y CSS3.
  • Backend: PHP con PDO.
  • Base de datos: MySQL / MariaDB.
  • Herramientas: XAMPP, VS Code y phpMyAdmin.

Qué hace el sistema

Registro

Un formulario pide nombre, apellido, DNI, correo y contraseña. Todos los campos son obligatorios y el sistema no deja registrar un DNI o un correo que ya existan.

Inicio de sesión

La persona ingresa con su correo y contraseña. Si son correctos, se guarda su información en la sesión de PHP y se la lleva a su panel.

Panel personal

Cualquier usuario logueado ve sus datos personales. Tiene un botón para cerrar sesión.

Panel administrador

Solo entra quien tiene el rol admin. Desde ahí puede:

  • Ver la tabla con todos los usuarios activos.
  • Buscar por nombre, apellido, DNI o correo.
  • Editar los datos de un usuario.
  • Archivar un usuario (queda guardado pero deja de aparecer en el listado).
  • Ver la lista de archivados y reactivar a alguien si hace falta.

Base de datos

Una sola tabla, usuarios. El archivado se hace con la columna archivado_en: si está vacía (NULL) el usuario está activo, y si tiene una fecha, está archivado.

CREATE TABLE usuarios (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nombre VARCHAR(50) NOT NULL,
  apellido VARCHAR(50) NOT NULL,
  dni VARCHAR(10) NOT NULL UNIQUE,
  email VARCHAR(100) NOT NULL UNIQUE,
  password VARCHAR(255) NOT NULL,
  rol ENUM('usuario','admin') NOT NULL DEFAULT 'usuario',
  creado_en DATETIME DEFAULT CURRENT_TIMESTAMP,
  archivado_en DATETIME NULL
);

Medidas de seguridad

Contraseñas con hash

La contraseña no se guarda tal cual. Al registrarse se guarda con password_hash() y al iniciar sesión se compara con password_verify(). Así, aunque alguien vea la base de datos, no conoce las contraseñas. 

$hash = password_hash($password, PASSWORD_DEFAULT);

if (password_verify($password, $usuario['password'])) {
    // login correcto
}

Consultas preparadas (PDO)

Nunca se pega lo que escribe el usuario directamente en la consulta SQL. Se usan parámetros, y eso evita la inyección SQL. 

$stmt = $conexion->prepare('SELECT * FROM usuarios WHERE email = :email');
$stmt->execute([':email' => $email]);

Sesiones y control de rol

Todas las páginas privadas comprueban que haya una sesión iniciada. Las páginas del administrador, además, comprueban que el rol sea admin. Si no, se responde "Acceso denegado". 

session_start();
if (!isset($_SESSION['usuario_id']) || ($_SESSION['usuario_rol'] ?? '') !== 'admin') {
    http_response_code(403);
    exit('Acceso denegado.');
}

Escapado de datos al mostrarlos

Todo lo que viene de la base de datos se muestra con htmlspecialchars() para que nadie pueda meter código HTML o JavaScript (ataque XSS). 

function escapar(string $valor): string {
    return htmlspecialchars($valor, ENT_QUOTES, 'UTF-8');
}

Otras medidas

  • Archivar solo por POST: nunca con un enlace, para evitar que se ejecute por accidente.
  • Token CSRF: protege las acciones del admin de pedidos falsos desde otros sitios.
  • Confirmación: el sistema pregunta antes de archivar.
  • Validación en el servidor: campos obligatorios, ID numérico, correo con formato válido.
  • Rol protegido: el formulario de edición no permite cambiar el rol.
  • Errores seguros: mensajes simples, sin mostrar detalles internos de MySQL.
  • Sin DELETE: los usuarios se archivan, así se conserva el historial.

Diseño: colores y tipografía

Para una perfumería elegí colores sobrios, una base clara y un tono ciruela como color principal. El dorado apagado se usa solo en detalles.

Tipografía: Georgia para los títulos (da un aire más elegante) y Segoe UI / Arial para el texto, para que se lea cómodo.

Así quedarían las variables en el CSS:

:root {
  --ciruela: #4a2340;
  --rosa: #e9d5dc;
  --dorado: #a8814f;
  --fondo: #fbf9fa;
  --texto: #2a2230;
}
Idea de diseño: las tablas del panel admin usan encabezado rosa suave, botones de editar en ciruela y el botón de archivar en un tono rojizo para que se note que es una acción delicada.
